    Create `jobs/csv_to_parquet/job.py`. This is the ETL job entry point. It is the only file in the
    project that imports awsglue (GlueContext). All transformation logic lives in transforms/, which
    imports only pyspark.sql.

    Structure:

    1. **Imports** (in this order):
       - `import os`
       - `import sys`
       - `import argparse`
       - `from pyspark.sql import SparkSession`
       - `from awsglue.context import GlueContext`
       - `from awsglue.job import Job`
       - `from transforms import read_csv, derive_temp_media, add_city_key, write_parquet`

       Do NOT import catalog.config. Do NOT read catalog/schema/temperaturas.json.

    2. **`apply_s3a_config(spark: SparkSession) -> SparkSession`** — applies the complete S3A
       configuration block as one unit. This function reads from `os.environ` directly (not from
       catalog.config) because catalog.config imports boto3 which is forbidden in the job context.

       Read the following environment variables (all are set in .env):
       - `AWS_ACCESS_KEY_ID`
       - `AWS_SECRET_ACCESS_KEY`
       - `AWS_REGION`
       - `S3_ENDPOINT` (the endpoint URL, e.g. http://floci:9000)
       - `PROJECT_NAME` (for deriving bucket names: `{PROJECT_NAME.replace('_', '-')}-raw` and
         `{PROJECT_NAME.replace('_', '-')}-curated`)

       Apply the following Hadoop configuration on spark.sparkContext._jsc.hadoopConfiguration():
       ```python
       hconf = spark.sparkContext._jsc.hadoopConfiguration()
       hconf.set("fs.s3a.endpoint", s3_endpoint)
       hconf.set("fs.s3a.path.style.access", "true")
       hconf.set("fs.s3a.connection.ssl.enabled", "false")
       hconf.set("fs.s3a.aws.credentials.provider",
                 "org.apache.hadoop.fs.s3a.SimpleAWSCredentialsProvider")
       hconf.set("fs.s3a.access.key", aws_access_key_id)
       hconf.set("fs.s3a.secret.key", aws_secret_access_key)
       hconf.set("fs.s3a.endpoint.region", aws_region)
       ```
       Return the spark session.

       Include a comment noting that catalog/config.py's bucket derivation (underscore→hyphen for S3,
       hyphen→underscore for Glue) is intentionally reproduced here inline, so the job does not depend
       on catalog.config. If PROJECT_NAME derivation ever changes, update BOTH catalog/config.py AND
       this inline derivation.

    3. **`main()`** — the job entry point:

       a. Parse `--JOB_NAME` argument with argparse (the Glue entrypoint convention, matching run.sh's
          invocation: `spark-submit ... job.py --JOB_NAME csv_to_parquet`).

       b. Build SparkSession with appName=job_name: `SparkSession.builder.appName(job_name)`.

       c. Call `apply_s3a_config(spark)` to apply S3A configuration.

       d. Build GlueContext: `glueContext = GlueContext(spark.sparkContext)`.

       e. Initialize the job: `job = Job(glueContext)` — this is required for Glue job lifecycle
          management even in local runs. Call `job.init(args.job_name, args)`.

       f. Read input: construct the raw prefix path:
          `raw_path = f"s3a://{project_name_raw_bucket}/temperaturas/"`.
          Call `raw_df = read_csv(spark, raw_path)`.
          Count rows read: `rows_read = raw_df.count()`.

       g. Apply transformations in order:
          - `df = add_city_key(raw_df)` — adds cidade_key column (normalized, lowercase, no accents)
          - `df = derive_temp_media(df)` — adds temp_media column

       h. **Empty-output guard (D-10)**: after transformations, assert the DataFrame is not empty:
          ```python
          if df.count() == 0:
              sys.exit("Job output is empty. Aborting — check input data at: " + raw_path)
          ```

       i. Write output to the curated bucket:
          `curated_path = f"s3a://{project_name_curated_bucket}/temperaturas/"`.
          Call `write_parquet(df, curated_path, partition_cols=["data_medicao", "cidade_key"])`.

          The compound partitionBy is per D-12: data_medicao + cidade_key = 3 dates × 6 cities = 18
          partitions. This supersedes the Phase 1 D-17 single-key partitioning.

       j. **Commit the job**: `job.commit()`.

       k. **Demo summary (D-11)**: print a summary with concrete numbers:
          ```
          ============================================
          ETL Job Complete: csv_to_parquet
          ============================================
          Rows read   : {rows_read}
          Rows written: {output_rows}
          Partitions  : 18 (data_medicao x cidade_key)
          Input path  : s3a://{project_name_raw_bucket}/temperaturas/
          Output path : s3a://{project_name_curated_bucket}/temperaturas/
          ============================================
          ```

          For output_rows, read back the written data: `written_df = spark.read.parquet(curated_path)`
          then `output_rows = written_df.count()`. If reading back fails, report 0 for output_rows
          but still print the summary.

    4. **Module-level committer comment** — place the comment block from RESEARCH.md §"What to
       document" at the top of the file, after the imports, explaining why no explicit S3A committer
       is configured (trivial scale, Floci GetObjectAttributes gap, integration test as safety net).

    5. **`if __name__ == "__main__": main()`** — standard entrypoint guard.

    **Critical constraints**:
    - The job reads the FULL PREFIX, not a single file. Do NOT read `input.csv` or any individual
      file. The path is `s3a://.../temperaturas/` — Spark reads all files matching that prefix.
    - Bucket names are derived inline from `PROJECT_NAME` and `os.environ`, not from catalog.config.
    - The job MUST NOT import catalog.config.
    - No endpoint URL, bucket name, database name, or credential appears as a string literal in the
      source. All come from `os.environ`.
