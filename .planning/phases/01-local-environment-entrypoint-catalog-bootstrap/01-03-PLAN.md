<objective>
Establish the single source of truth for the table schema, register it in the emulated Data Catalog
idempotently, and get sample data into the emulated S3 — so that one command on a clean clone ends
with a populated catalog and no AWS credential anywhere.

Purpose: the schema single-source mechanism is the highest-stakes open question in the project. If
it is not settled here, `bootstrap.py` and the Phase 3 Terraform diverge silently and the divergence
only surfaces in production. Whatever this plan writes is binding on Phase 3.

Output: `catalog/schema/temperaturas.json`, `catalog/config.py`, `catalog/bootstrap.py`,
`catalog/seed.py`, three sample CSVs and their synthetic-data disclaimer.
</objective>

    Create `catalog/schema/temperaturas.json`. This is the single source of truth for the catalog
    object (CAT-03, D-01). Its shape is neutral and minimal — designed to be read and edited by an
    adopter, not to mirror the verbose Glue API request shape, whose fields carry no meaning for
    someone adapting a template (D-02). Each consumer maps from this neutral form to its own API:
    `catalog/bootstrap.py` today, Terraform's `jsondecode(file(...))` with `dynamic` blocks in
    Phase 3. Add no build step and generate no derived file — the file is read directly by both, and
    that is the only way the single source is actually single.

    Top-level keys, all required:
      - `table` — the string `temperaturas`.
      - `description` — a one-line human description that states the data is synthetic.
      - `bucket` — the string `curated`. This names which PROJECT_NAME-derived bucket the table sits
        in; `catalog/config.py` resolves it to a concrete bucket name. Keeping it relative is what
        lets an adopter change PROJECT_NAME and have the table follow (D-16).
      - `location` — the bucket-relative prefix `temperaturas/` (D-03: relative location).
      - `columns` — an ordered array of `{name, type, comment}` objects with Glue type names:
        `cidade` (string), `temp_min` (double), `temp_max` (double), `temp_media` (double, with a
        comment noting it is derived on write by the Phase 2 job). Partition keys are NOT repeated
        here.
      - `partition_keys` — an ordered array of `{name, type, comment}`: `data_medicao` (string).
      - `partitions` — an array of `{values: [...]}` entries, one per registered partition, where
        `values` is ordered to match `partition_keys`. Three entries (D-17): `["2026-01-15"]`,
        `["2026-01-16"]`, `["2026-01-17"]`. Three is enough for the registration loop to actually
        be a loop and for a Phase 2 test to assert per-partition counts, without inflating repo size
        or run time. Using an ordered `values` array rather than a flat string generalizes to
        multi-key partitioning without a shape change.
      - `storage` — an object with `format` (`parquet`), `input_format`
        (`org.apache.hadoop.hive.ql.io.parquet.MapredParquetInputFormat`), `output_format`
        (`org.apache.hadoop.hive.ql.io.parquet.MapredParquetOutputFormat`), and `serde`
        (`org.apache.hadoop.hive.ql.io.parquet.serde.ParquetHiveSerDe`).
      - `table_parameters` — an object with `classification` set to `parquet` and `EXTERNAL` set to
        `TRUE`.

    This table describes the curated Parquet output, not the raw CSV input. That is deliberate: the
    Phase 2 job reads the raw CSV through an explicit path and needs no catalog entry for it, while
    the Phase 2 Athena assertion queries the curated output through the catalog — and PROJECT.md's
    Out of Scope list forbids a second table.

    Create `catalog/config.py` — the one place configuration is resolved, so that swapping the
    emulator costs one environment variable and nothing else. Functions:
      - `project_name()` — returns `PROJECT_NAME` from the environment; raises a `RuntimeError`
        naming the variable when it is unset or empty.
      - `raw_bucket()` and `curated_bucket()` — return `f"{project_name().replace('_', '-')}-raw"`
        and `...-curated`. The underscore-to-hyphen transform is required because S3 bucket names
        forbid underscores.
      - `database_name()` — returns `f"{project_name().replace('-', '_')}_db"`. The
        hyphen-to-underscore transform is required because a Glue database name containing a hyphen
        must be quoted in every Athena query. These two transforms are the derivation rule Phase 3's
        Terraform must reproduce with the same two `replace` calls; document that in the module
        docstring so a Phase 3 author cannot miss it.
      - `endpoint_url()` — returns `AWS_ENDPOINT_URL` from the environment; raises a `RuntimeError`
        naming the variable when unset or empty. An empty endpoint would make boto3 fall through to
        real AWS regional endpoint resolution, which is exactly the accident this raise prevents
        (T-01-03).
      - `glue_client()` and `s3_client()` — return `boto3.client("glue", endpoint_url=endpoint_url())`
        and the same for `"s3"`. Use only standard boto3 API calls throughout this phase; never a
        Floci-specific admin or debug endpoint, so that swapping to another emulator costs one
        variable (PITFALLS Pitfall 8).
      - `load_schema(path)` — opens the given path read-only and returns `json.load` of it. Open in
        read mode only; nothing in this repository writes the schema file at runtime, which is what
        makes concurrent consumers safe.

    Do not add a Spark or PySpark import to this module or to anything under `catalog/`. The Phase 2
    Spark job declares its own schema and does not read this file (D-04) — `transforms/` must stay
    pure and free of file I/O to remain unit-testable without Glue or AWS. The Glue-type to
    Spark-type correspondence becomes a documented mapping in Phase 4, not a code coupling.

  <action>
    Create `catalog/bootstrap.py`. It runs inside the `tools` service (D-05) — python:3.11-slim with
    boto3 — because it makes only boto3 API calls and never touches Spark. Running it on the Glue
    image would force every adopter to pull roughly 4.8 GB before their first API call, which
    attacks the project's core value directly.

    Functions:

    `validate_schema(schema)` — raises a module-level `SchemaError` with a message naming the
    offending key when: `columns` is missing or empty (a table with no columns is meaningless);
    `partition_keys` is missing; `storage` lacks any of `input_format`, `output_format`, `serde`;
    `bucket` or `location` or `table` is missing or empty; or any entry in `partitions` has a
    `values` array whose length differs from the `partition_keys` length. An empty `partitions`
    array is NOT an error — it is a legitimate unpartitioned table, and the script reports "0
    partitions registered" and exits 0. Defining these outcomes explicitly is the point: an
    adopter who deletes a column or a partition entry must get a named error or a clear report, not
    a silently degenerate catalog object.

    `build_table_input(schema, location_uri)` — maps the neutral schema shape to the Glue API
    `TableInput` dictionary (D-02: the mapping lives on the consumer side, not in the file). Sets
    `Name`, `Description`, `TableType` to `EXTERNAL_TABLE`, `Parameters` from `table_parameters`,
    `PartitionKeys` from `partition_keys`, and a `StorageDescriptor` carrying `Columns`, `Location`
    set to `location_uri`, `InputFormat`, `OutputFormat`, and `SerdeInfo` with
    `SerializationLibrary` set to the schema's serde.

    The `location_uri` is built as `s3://{curated_bucket()}/{location}` — the `s3://` scheme, not
    `s3a://`. This is deliberate and worth stating in a module comment: real AWS Glue and the
    Phase 3 Terraform both write `s3://` into a table's Location, so writing anything else here
    would create exactly the local/prod divergence CAT-03 exists to prevent. The `s3a://` scheme
    belongs to Spark's filesystem access in Phase 2, which is a different concern from catalog
    metadata.

    `ensure_database(glue, name, description)` — calls `create_database`; catches a `ClientError`
    whose error code is `AlreadyExistsException` and calls `update_database` instead (D-08:
    create-if-absent, update-if-present). Let any other error code propagate.

    `ensure_table(glue, database, table_input)` — calls `create_table`; on `AlreadyExistsException`
    calls `update_table` with the identical `TableInput`. Re-running after editing the schema file
    applies the change, which is the behaviour that makes the single source of truth actually
    authoritative. Never delete and recreate: that would be destructive if this script were ever
    pointed at a real AWS account.

    `ensure_partitions(glue, database, table, schema, location_uri)` — iterates over
    `schema["partitions"]` and registers each one individually with `create_partition`, building the
    partition's own `StorageDescriptor` with a Hive-style location
    `{location_uri}{key}={value}/` joined across all partition keys. Registration is one call per
    partition, in a loop, because the emulator's Glue surface does not implement the batched form of
    this operation — and a loop is forward-compatible with real AWS, which supports both. Do not
    replace this loop with the batched call; a future contributor "optimizing" it silently breaks
    every local run. On `AlreadyExistsException` for a given partition, skip it and continue:
    partitions are left in place by decision (D-08), unlike the table. Return the count of
    partitions newly created and the count skipped.

    `main()` — loads the schema via `catalog.config.load_schema`, validates it, resolves the
    database name and curated bucket from `catalog.config`, ensures database then table then
    partitions, prints one line per step naming what it did (created vs updated vs skipped) so
    `run.sh`'s captured output is useful when a step fails, and returns 0. Guard the entrypoint with
    the standard main check and exit with `main()`'s return value.

    Import `catalog.config` as a module rather than duplicating any name derivation or client
    construction here — there is exactly one derivation site.
  </action>
