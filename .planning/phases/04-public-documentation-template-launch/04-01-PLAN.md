<task type="auto">
  <name>Wave 2a — docs/KNOWN_DIFFERENCES.md</name>
  <files>docs/KNOWN_DIFFERENCES.md</files>
  <action>
    Create docs/KNOWN_DIFFERENCES.md with a single table.

    Table columns: What's different | Local (Floci) | Real AWS | Impact | Workaround

    Rows (verbatim from STATE.md decisions and 04-CONTEXT.md D-05/D-06/D-07):

    1. **IAM enforcement**
       - Local: IAM is not enforced; any principal can perform any action
       - AWS: IAM policy is gatekept for every API call
       - Impact: Passing locally proves Spark logic, not IAM policy
       - Workaround: Review terraform/iam.tf for the policy the template intends

    2. **Job bookmarks**
       - Local: Job bookmarks are not implemented
       - AWS: Bookmarks track processed files between runs
       - Impact: Re-running the job re-processes all files
       - Workaround: None locally; design the pipeline assuming no bookmark support

    3. **Crawlers and StartJobRun**
       - Local: Floci does not emulate Glue crawlers or StartJobRun
       - AWS: Crawlers auto-discover schemas; StartJobRun is the standard job invocation API
       - Impact: Schema registration uses bootstrap.py (boto3 CreateTable/CreatePartition), not a crawler
       - Workaround: Use ./run.sh bootstrap to register schemas

    4. **from_catalog unavailable locally**
       - Local: The Glue Catalog client is JVM closed-source; endpoint redirection is unavailable
       - AWS: from_catalog works and reads from the real Data Catalog
       - Impact: The job uses explicit s3a:// paths via from_options, not from_catalog
       - Workaround: No local workaround; from_catalog is only available on real AWS

    5. **Athena-via-DuckDB dialect gap**
       - Local: Floci serves Athena through a DuckDB sidecar (floci-duck)
       - AWS: Athena uses Trino under the hood
       - Impact: Only a portable SQL subset is guaranteed: SELECT, WHERE, COUNT, AVG, GROUP BY, ORDER BY
       - Workaround: Keep SQL portable; the full Trino dialect is not tested locally

    6. **Terraform validated but never applied**
       - Local: terraform init -backend=false, terraform fmt -check, terraform validate run in CI
       - AWS: terraform apply requires real credentials and a real account
       - Impact: Passing Terraform checks proves the module is syntactically valid and well-formed; it does not prove the resources work in a real account
       - Workaround: Review terraform/ before applying to a real account

    7. **Floci Update* gap** (per D-05)
       - Local: Floci does not implement UpdateDatabase or UpdateTable
       - AWS: Both are available
       - Impact: Schema edits to a live Floci container are not absorbed without a restart
       - Workaround: Run ./run.sh down && ./run.sh up to restart Floci and re-bootstrap

    8. **Docker commands outside run.sh break on Git Bash** (per D-06)
       - Local (Windows Git Bash): MSYS2 rewrites POSIX path arguments before Docker sees them
       - Local (Linux/macOS): Not affected
       - Impact: Ad-hoc docker compose commands with path arguments silently misfire on Windows
       - Workaround: Always use ./run.sh, which sets MSYS_NO_PATHCONV=1 internally

    9. **Floci GetTables fidelity gap** (per D-07)
       - Local: GetTables on a nonexistent database returns [] (empty list)
       - AWS: Raises EntityNotFoundException
       - Impact: A nonexistent database and an empty database are indistinguishable through GetTables alone
       - Workaround: Confirm the database name is derived correctly via catalog/config.py (PROJECT_NAME.replace('-', '_') + '_db')

    10. **Append mode row duplication**
       - Local: The job writes in append mode
       - AWS: Same behavior with append mode
       - Impact: Running ./run.sh demo twice without ./run.sh down in between doubles the row count in each partition
       - Workaround: Run ./run.sh down before re-running demo, or clear the curated prefix between runs

    Do NOT add rows for behaviors that are correctly documented in the README.
  </action>

  </verify>
