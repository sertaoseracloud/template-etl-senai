  <action>
    Create `docker-compose.yml` at the repository root with three services and no top-level
    `version:` key (obsolete in Compose v2).

    Service `floci` — `image: floci/floci:1.5.11` (ENV-02: pinned by exact version tag; the mutable
    rolling tag is forbidden because Floci is a young 2026 project and a template promises
    reproducibility). Publish `${FLOCI_HOST_PORT:-4566}:4566`. Under `environment:` set
    `FLOCI_HOSTNAME=floci` (so URLs Floci returns resolve on the Compose network rather than to
    localhost), `FLOCI_PORT=4566`, and `FLOCI_STORAGE_MODE=memory`. These three are fixed
    compose-network facts, not adopter configuration, so they belong under `environment:` and not in
    `.env`. Author NO `healthcheck:` key: the floci image ships its own HEALTHCHECK instruction
    (confirmed in `docker/Dockerfile.native` in floci-io/floci per ARCHITECTURE.md), and duplicating
    it here would create a second source of truth. Do NOT attach `env_file:` to this service — the
    emulator must not receive the adopter's credential variables.

    Service `tools` — `build:` with `context: .` and `dockerfile: docker/tools/Dockerfile`
    (D-05: the bootstrap runs here, on python:3.11-slim with boto3, never on the Glue image, because
    forcing a ~4.77 GB pull before an adopter's first API call attacks the project's core value
    directly). Set `profiles: ["tools"]` so `docker compose up` never starts it. Set
    `depends_on: floci: condition: service_healthy`. Set `working_dir: /workspace` and mount the
    repository read-only with `- .:/workspace:ro` — one mount line that needs no edit when Phase 2
    adds `transforms/`, `jobs/`, and `tests/`, and read-only because nothing in this container ever
    writes to the repository. Set `env_file: - .env`.

    Service `glue` — `image: public.ecr.aws/glue/aws-glue-libs:5` (ENV-02). Set
    `profiles: ["glue"]` (ENV-07: invoked as an ephemeral `docker compose run --rm` task, never a
    long-lived service; this is also what keeps `docker compose up` from fetching the ~4.77 GB image
    during this phase, per D-07). Set `depends_on: floci: condition: service_healthy` (ENV-03 —
    this is the requirement's literal subject). Set `working_dir: /home/hadoop/workspace` and mount
    `- .:/home/hadoop/workspace` read-write (Spark needs to write scratch state). Set
    `env_file: - .env`.

    Use `env_file:` rather than `environment:` with `${VAR}` substitution for every adopter-supplied
    value. This is load-bearing, not stylistic: `${VAR}` inside a compose file resolves from the
    host shell first and only then from `.env`, so a developer with real AWS credentials exported in
    their shell would silently have them injected into the containers. With `env_file:`, Compose
    reads the values straight out of `.env` and the host shell is not consulted. This is the
    mitigation for T-01-03 and the resolution of the ENV-04 adjacency edge (what happens when the
    same variable is defined in two places).

    Create `.env.example` at the repository root documenting every variable the project reads and
    nothing else. Lead with a comment block instructing `cp .env.example .env`. The variables are:
      - `PROJECT_NAME=template-etl` — the single naming source (D-16). Document in comments the
        exact derivation every consumer applies: raw bucket `${PROJECT_NAME}-raw`, curated bucket
        `${PROJECT_NAME}-curated`, Glue database `${PROJECT_NAME with hyphens replaced by
        underscores}_db`. State why the two transforms differ: S3 bucket names forbid underscores,
        and a Glue database name containing a hyphen must be quoted in every Athena query. An
        adopter changes this one variable and the whole rename follows — no per-resource overrides
        exist, by decision.
      - `AWS_ENDPOINT_URL=http://floci:4566` — the emulator endpoint on the Compose network.
        Comment that `run.sh` refuses to run when this is empty, precisely so a local command can
        never reach a real AWS account.
      - `AWS_DEFAULT_REGION=us-east-1` — the region variable botocore actually honours. Do NOT add
        the SDK-v2/Lambda spelling of the region variable; it is not read by boto3 and putting it
        here would document a knob that does nothing.
      - `AWS_ACCESS_KEY_ID=test` and `AWS_SECRET_ACCESS_KEY=test` — dummy values; Floci accepts any
        non-empty credential. Comment explicitly that a real AWS credential must never be placed
        here, that `.env` is gitignored and `.env.example` is not.
      - `FLOCI_HOST_PORT=4566` — the host port the emulator API is published on.

    Do NOT add an SSL-disable variable and do NOT add the SDK-v2 region spelling. Neither is read by
    the Glue container, the tools container, or Floci. SSL against the emulator is controlled by the
    Spark configuration key `spark.hadoop.fs.s3a.connection.ssl.enabled`, which Phase 2 owns.
    Documenting a variable nothing reads is worse than omitting it: an adopter will change it, see
    no effect, and lose trust in the whole file.
  </action>
